nimble-starter

A standard way to build small, installable web apps.

Made to cater the nimble suite of productivity apps by Monco.io. Sign in with Google, keep the data in the user's own Drive, no database to run, and the nimbleUI look from the first commit. A starter, a design system and a handful of rules.

Use this template See the four steps

What you get

Working and tested from the first commit, so a new product starts at the interesting part.

Google sign-in

A long-lived session with no user table: the refresh token is sealed in an encrypted, httpOnly cookie. The server keeps nothing.

Data in the user's Drive

One JSON file in the app's private folder. Safe sync: no save after a failed load, conflicts asked, offline edits kept and retried.

Installable

A web app manifest and icons make it installable on phones and desktops. An install button sits in the account menu and on the product page.

nimbleUI

Tokens, components and behaviours; dark and light change only colour. Kept current by an automatic sync from the kit.

Product page included

Landing, privacy and terms pages that the Google consent screen can link to, plus the app itself at /app.

Tests without Google

The whole sign-in loop runs against a fake Google, and the sync rules against a fake Drive. npm test stays green.

The shape of an app

The server is a thin bridge to Google. Everything the user owns lives in their own Drive.

Four steps

Copy the template

On GitHub, Use this template, or copy the folder.

Name it

One command fills in the name, accent and tagline.

Connect Google

Create an OAuth client, copy .env.example to .env.

Build and deploy

Replace the demo, keep the tests green, push to any Node host.

node scripts/init.mjs "My App" --accent indigo --tagline "One sentence about what it does."
npm install
npm run dev      # http://localhost:3000
npm test

The rules that keep it simple

Each one is protected by a test. If a change needs to break one, discuss it first.

Stay stateless

No database, no files for user data, no tokens kept. The only secrets are environment variables.

Never save after a failed load

The app is read-only until the load succeeded. A newer Drive copy is a conflict the user resolves, never silently overwritten.

Dark and light change only colour

Sizes, spacing, radii and shadow geometry are defined once. A check enforces it.

User text is text

Build DOM with textContent; no inline scripts or styles, so a strict CSP holds.

Phones first-class

The top bar keeps only the essentials; the rest lives in the account menu. No horizontal scroll at 375px.

Dependency-light

Express and nothing else. Ask before adding a dependency or a database.

Checklist for a new app

  • node scripts/init.mjs run; privacy and terms written and reviewed
  • Google OAuth client created; redirect URI added for local and production
  • .env set locally; variables set on the host; PUBLIC_URL set
  • Demo replaced; Drive.change(doc) called after every edit
  • npm test green; checked at 375px and in both themes
  • App added to the kit's sync list so design updates arrive as pull requests
