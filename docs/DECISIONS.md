# nimbleUI — decisions log

## Settled
1. **Name/home:** nimbleUI, repo `dferreiramarques/nimbleui-design-system` (public, MIT), also installed as the Claude skill `nimbleui-design-system`.
2. **Base:** the Roadmaps system (landing section of `app.css` / `product-page.css`), which Taskboards and Diagramico product pages already share.
3. **Dark/light change only colours** (David's global rule). Verified: 0 non-colour diffs in the gallery for all accents.
4. **One accent per product** via `data-accent`: emerald (Roadmaps), rose (Taskboards), indigo (Diagramico). Accent = 6 tokens.
5. **No inline script / `style=""`** (CSP). State via attributes (`aria-pressed`, `hidden`, `data-*`).
6. **Product page template** with fixed section order; template + recipe in the repo and the skill.
8. **Patterns documented** in `docs/PATTERNS.md` (18 patterns + migration map); css-todo ones get CSS when their app is migrated.
7. **Done:** `behaviors.js` (sort, edit, dialog, confirm, menu, tabs, toast), switch/check/radio, spinner, skeleton, sync chip, list rows, tooltip, auto theme, compact density. Verified in the gallery: 0 non-colour diffs across 3 accents × 2 densities.

## Decided (2026-11-15, after the audit)
- **A. Scope: unify all apps.** nimbleUI becomes the base of the Roadmaps, Taskboards and Diagramico apps. One font stack (Inter + JetBrains Mono); Figtree and IBM Plex are retired. Diagramico's 13px/dense editor UI becomes an opt-in `data-density="compact"` (size change, never tied to theme). Migration of the Taskboards and Diagramico apps is a separate, per-repo task (visual regression risk).
- **C. Drag: pointer events** (touch, autoscroll, Esc cancels, keyboard reorder). Indicator is the `.drop-slot` class, never inline `style`. Roadmaps migrates off native HTML5 drag.
- **D. Theme: auto by default** (`prefers-color-scheme` when nothing is stored; choice auto/light/dark). One shadow geometry for both themes; Diagramico's dark `0 8px 24px` becomes the light `0 6px 20px` value (or the reverse) — a single value in `:root`.
- **G. Source of truth: this repo.** Roadmaps/Taskboards/Diagramico copy `tokens.css` + `components.css` from here; `product-page.css` is no longer generated from `app.css`, and the drift test compares against this repo.
- **Defaults taken without asking:** E (CSP) → strict, no `unsafe-inline`; Diagramico must move its inline script/style to files when it migrates. F (naming) → BEM modifiers (`.btn--primary`), so `.btn.primary` and `.ibtn.on` are renamed on migration. H → follows D (auto), legal pages included.

## Migration log
- **Roadmaps (done, 2026-11-15):** `public/nimble/` = copy of `src/`; `app.css` slimmed to app-specific rules; drag (cards + tabs) → `data-sortable`; account menu → `.menu` + `data-menu-toggle`; dialogs → `NimbleUI.dialog`; toast → `NimbleUI.toast`; sync chip → `.sync[data-state]`; theme → `theme.js` (auto by default, reuses the `roadmaps-theme` key via `<meta name="nimble-theme-key">`); `product-page.css` and the old drift test removed. Kit changes it forced: touch drag starts on the first move after a 250ms hold (a still long-press stays free for context menus); `data-sortable-keyboard="off"`; sort keys ignored when the app already handled the key (`defaultPrevented`); items that are themselves buttons can be dragged; menu only refocuses its toggle if focus is still inside; `theme.js` meta key + `data-theme-icon`. Still app-local (css-todo patterns): colour tabs + colour popover, share dialog, public page.
- **Taskboards, phase 1 (done, 2026-11-16, branch `nimbleui-migration`):** `nimble/` copied (root + `public/`); `style.css` Fluent `--f-*` tokens became aliases of nimble tokens (colours, radii, shadows), Inter replaces Figtree, accent via `data-accent="rose"`; theme via `theme.js` (auto, key `taskboards-theme`, app and viewer repaint on `nimble:theme`); landing/privacy/terms use `tokens.css` + `components.css`; `product-page.css` removed; service worker cache v57. Product pages verified identical to `main` (only a stray link underline fixed). **The app loads `tokens.css` only, not `components.css`:** its own `.card`, `.toast`, `.topbar`, `.modal*`, `.btn`-like classes would collide with the kit's. Kit additions it forced: `.lp-demo`, `.doc__date`, `.topbar` gap at 480px, `nimble:theme` event.
- **Taskboards, phase 2 (open):** replace app components one at a time with the kit's (user pill → `.menu`, modals → `NimbleUI.dialog`, toast with dedupe/types promoted into the kit, card/column drag → `data-sortable` incl. shelves, matrix and drop overlays), then load `components.css` in the app. Needs its own PR: 3500-line `app.js`, no tests, custom drag across 4 zones.
- **Diagramico, phase 1 (done, 2026-11-16, branch `nimbleui-migration`):** kit copied to `assets/nimble/` (a public dir, so the server only lost `/product-page.css`); landing and guides (generator + `guides.css` + regenerated pages) use `tokens.css` + `components.css` with `data-accent="indigo"`, verified identical to `main` (both themes, 1280/375px); `product-page.css` removed. **App:** loads `tokens.css` only; its token names (`--panel`, `--line`, `--ink`, `--accent`, `--shadow`, `--sans`) alias nimble tokens; Inter for the UI chrome; `data-density="compact"`; `--theme` (new kit token) keeps feeding the canvas palette; the auto theme is resolved by an early script (nimble tokens need `data-theme`) with `data-host-theme` preserving a theme forced by an embedding page; one shadow geometry for both themes (the 0-diff check passes in the app). **Exception to "Plex retired": the diagram canvas keeps IBM Plex** (`SANS`/`MONO` constants, `FONT_FACES`), because boxes auto-fit their text: changing the font would reflow saved diagrams and change PNG/SVG exports. Phase 2 (open): replace chrome components (modals, drawer, toast, menus) with the kit's and load `components.css` in the app; inline script/style CSP cleanup.
- **Taskboards, phase 2 (branch `nimbleui-phase2`, stacked on phase 1):** the kit is loaded as `components.layered.css` (cascade layer `nimble`, so the app's own `.card/.toast/.topbar` win); card, help and share/invite modals run on `NimbleUI.dialog` through `data-dialog-overlay` / `data-dialog-panel` (focus trap, Esc, backdrop, focus restore) and the app's old open/close/Esc code is gone; toast is `NimbleUI.toast` (kit gained tones success/info/warn/error/loading, de-duplication `(×n)`, duration); the account pill became a kit menu (button + `data-menu-toggle`). Compat overrides in `style.css` keep the app's metrics. **Not done:** card/column/tab drag and the shelves, matrix and drop overlays still use the app's own pointer code (a separate step: four zones, ghost, autoscroll, long-press edit mode).
- **Diagramico, phase 2 (branch `nimbleui-phase2`, stacked on phase 1):** only `behaviors.js` joins the editor: the toast is `NimbleUI.toast` (inverted look from the editor's own CSS, hidden in the embed) and the export/insight/confirm modal opens with `NimbleUI.dialog` (focus trap, aria-modal, focus restore; Esc/backdrop stay with the app via `data-static`). **The kit's component CSS is not loaded in the editor:** the app has no reset of its own, so the kit's base rules (`box-sizing`, `line-height`, `.topbar`/`.brand`) changed 200+ elements (e.g. the doc bar 34px to 44px). Drawer, tooltips, panels and context bars stay app-local (css-todo patterns).
- **Kit follow-up:** split `components.css` into `base.css` (reset, body, type) and component modules, so a dense or legacy UI can take the dialog/menu/toast CSS without the reset.
- **Taskboards, phase 3 (branch `nimbleui-drag`, stacked on phase 2):** card drag runs on `data-sortable` for the four lists (To do, In progress, Archive, Done) with one `nimble:sort` handler that calls the app's `moveOrReorderCard` (so confetti, toast, sortOrder and Drive saving are unchanged). Collapsed shelves and whole columns are `data-sortable-drop` targets, hover state keeps the app's `.drag-over`, the ghost is the kit's clone of the card, and the app's ~250 lines of ghost, zone, indicator and autoscroll code are gone. Behaviour changes: touch drag needs a short hold before moving (a swipe scrolls, a still long-press arms the card as before); cards are keyboard-sortable (Space, arrows, Space); the armed (red) card and viewers of a team board do not drag. **Still app-local:** board tab drag with page flipping.
- **Kit fixes this forced:** the drag ghost keeps the item's classes, so an app's `.card { position: relative }` put it back in the layout (ghost rules are now `!important`); the page autoscrolled in a fixed `overflow:hidden` layout, shifting the board under the pointer (now only when scrollable); `data-no-drag`, `sortstart/sortend`, drop targets, hover class option, `cancel()/active()`.
- **Next:** the kit CSS split (`base.css` vs components), then Diagramico's drawer and panels.
